# 调研：现有的 Collab 是怎么组织的

结论先说：所有合集都是「一个 mod + CollabUtils2 认的目录结构」，区别只在素材放得多细。
素材真正会打架的地方，是贴图/音频/对话 id 这些**全局唯一**的名字，目录结构只能解决一半。

## 1. 样本

| 合集 | 规模 | 目录特点 |
|---|---|---|
| The 2020 Celeste Spring Community Collab | 老牌，CollabUtils2 就是为它写的 | `Maps/SpringCollab2020/<大厅>/...`，心门 `ZZ-HeartSide` |
| Strawberry Jam Collab（SJ2021） | 5 个大厅 116 张图（含 5 个心门）；包 90MB、约 2.8 万个文件，音频另拆 3 个包各 300MB | 图按作者命名；素材 `SJ2021/<作者>/`；音频 `sj21_<作者>_sfx` |
| Acorn Collab（2026，20 张图） | 中大型 | 图按图名；素材 `AcornCollab/<图名>/`；音频 `AcornCollab_<图名>.bank`；代码单独一个 mod |
| Surprise Collab（2026，5 张图） | 小型，作者自述「打包很乱」 | 反例：文件直接丢在 `bgs/` 根目录，作者目录大小写不统一，音频叫 `lobby.bank` |
| 中文社区写法（bilibili wiki 合集教程） | — | bin 用英文图名或「作者+序号」；`1-Maps` / `1-Submissions` 是常规叫法；支持大厅套大厅 |

镜像站 `celeste.weg.fan` 里 Collab/Contest 分类现在有 142 个作品（2026-11-23 拉的全量目录）。

## 2. 共同点：结构由 CollabUtils2 定死

CollabUtils2 是靠**路径**认人的，不看配置：

- 根目录有 `CollabUtils2CollabID.txt`，内容就是合集名，才会被当成合集。
- `Maps/<合集>/0-Lobbies/<序号>-<大厅>.bin` 是入口；只有大厅出现在章节选择里。
- `Maps/<合集>/<大厅>/<图>.bin` 自动属于关卡组 `<合集>/<大厅>`，大厅里的章节面板就指向它。
- `Maps/<合集>/0-Gyms/<大厅>.bin` 是健身房，跟大厅同名就能对上。
- `Maps/<合集>/<大厅>/ZZ-HeartSide.bin` 是心门，集齐心才解锁。
- `0-Lobbies/0-Prologue.bin` 是序章，不打完不解锁大厅。
- 大厅里的关卡组完成度 flag 叫 `CollabUtils2_MapCompleted_<bin名>`。

所以模板的目录不能自己发明，只能在这个骨架上加「作者/地图」两层。

## 3. 共同点：素材都落在「合集名」命名空间下

四个样本无一例外：贴图路径第一段就是合集名（`SJ2021/`、`AcornCollab/`、`ExampleCollab/`）。
原因很实际：Everest 里同名路径是**后加载的盖掉前面的**，不放进自己的命名空间，早晚盖到别人的贴图，或者被别人盖。

## 4. 差异：第二层放「作者」还是「图名」

- SJ2021 一人一张图，所以 `SJ2021/<作者>/` 就等于 `SJ2021/<图>/`，看不出区别。
- Acorn 20 张图、作者和图的对应不唯一，于是统一改成 `AcornCollab/<图名>/`。
- 一旦一个作者交两张图，`<作者>/` 下面必须再分一层 `<图>/`，否则同一个 `bg.png` 会互相覆盖。

## 5. 会被忽略但一定会踩的坑

1. 路径大小写敏感。`Kelsey` 和 `kelsey` 是两个目录。
2. decal 文件名以数字结尾会被当成动画帧，单张图会渲染错。
3. 音频 bank 和 `.guids.txt` 必须同名同目录，少一个就整包不加载。
4. 对话 id 里的空格、横杠、斜杠、加号都要换成下划线；换错就只剩键名。
5. 懒加载打开后不交 `.texturecache.txt`，玩家第一次进图会卡顿。
6. 图越大越要拆包：SJ2021 把音频拆成 3 个 300MB 的包，否则下载器直接崩。
