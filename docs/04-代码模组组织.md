# 代码 mod 的组织方式

整个仓库就是一个 Everest mod，代码按「用途」分目录，不按「类名首字母」也不按「谁的图」分。
这是照着 [DBBHelper](https://github.com/HiBlueBerry/DBBHelper) 的工程组织来的，好处是别人打开仓库能按用途找代码。

```
Source/
├─ ExampleCollab.csproj                 工程文件，编译产物拷到 ../bin
├─ Collab_CoreModule/                   模块本身和到处要用的东西
│   ├─ HelperModule/                    Module / Settings / Session / SaveData 四件套
│   └─ CG_RelativeContent/              数学、曲线这类纯工具
├─ Collab_Mechanism/                    框架层：管理器、hook、渲染管线
│   └─ SourceManager/                   各种 Manager，Load/UnLoad 成对
├─ Collab_VanillaEntity/                对原版实体的改造、换皮、变体
├─ Collab_SpecialEntity/                合集自己的新实体，一个家族一个子目录
├─ Collab_StyleGround/                  自定义背景/前景
└─ Patch/                               MonoMod patch，一个目标一个文件
```

## 和前缀对应的约定

| 目录 | 放什么 | 不该放什么 |
|---|---|---|
| `Collab_CoreModule/HelperModule` | `ExampleCollabModule` 和它引用的 Settings/Session/SaveData | 任何实体逻辑 |
| `Collab_CoreModule/CG_RelativeContent` | `CollabMath` 这种纯函数 | 依赖 Scene 的代码 |
| `Collab_Mechanism` | `CollabEffectManager`、`CollabEntityManager` 这类全局管理器 | 单个实体的行为 |
| `Collab_VanillaEntity` | 改原版实体行为的类 | 全新的实体 |
| `Collab_SpecialEntity` | 全新的 Entity / Trigger，按家族建子目录 | 管理器 |
| `Patch` | 只放 `On.` / `IL.` 补丁 | 业务逻辑 |

## 命名空间

根是 `Celeste.Mod.ExampleCollab`：

- 模块、设置、存档：`Celeste.Mod.ExampleCollab`
- 实体（不管在哪个目录）：`Celeste.Mod.ExampleCollab.Entities`
- 管理器、渲染：`Celeste.Mod.ExampleCollab.Mechanism`

目录名带 `Collab_` 前缀只是给人看的，不体现在命名空间里，和 DBBHelper 的 `DBB_VanillaEntity` + `...Entities` 一致。

## 工程文件和 everest.yaml 的对应

- `Source/ExampleCollab.csproj` 的 `AssemblyName` = `ExampleCollab`。
- 编译后自动拷到 `bin/ExampleCollab.dll`（csproj 里的 `CopyModAssembly` target）。
- `everest.yaml` 的 `DLL: bin/ExampleCollab.dll` 指的就是它。
- 引用 Celeste 的 DLL 一律 `Private=false`，不要把 Celeste.dll 拷进 mod。
- 没有 Celeste 的引用程序集时用 `-p:CelesteRoot=<目录>` 指过去。

## 特效（HLSL）

`Effects/` 下源码和编译产物分开：源码在 `Effects/<合集>_Source/*.hlsl`，编译好的 `.cso` 放 `Effects/`，
`CollabEffectManager` 的名单里加名字就加载。编译命令见 `Effects/README.md`。

## 工具

`tools/CollabTools/` 是开发期用的命令行工具（查素材命名、并对话），不是 mod 的一部分，不会进发布 zip。
它也要引用 `net8.0`，跟 `Source/` 分开编：

```
dotnet run --project tools/CollabTools -- check .
```
